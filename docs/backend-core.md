# Расчётное ядро: этап 1

Реализовано 14 ноября 2026 года. Поиск и чистая сборка отчёта добавлены на
[этапе 2](backend-search.md); API и инструменты правок относятся к этапу 3.
Сейчас публичный маршрут — `GET /api/health`.

## Модули

- `backend/app/models.py`: позиции, вопросы, предложения, цепочка поправок,
  статистика и отчёт по `docs/api.md`. `Edit` — discriminated union по `kind`;
  для отдельной правки используется `TypeAdapter(Edit)`. Payload P0 проверяется
  по виду правки, исправляемые поля — по ограничениям `Offer`. Модели P1/P2
  подготовлены, выполнение этих действий не реализовано.
- `FoundOffer` и `ResearchRun` хранят исходное предложение и условия источника
  отдельно от `OfferEntry`. При JSON-сохранении результата поиска дробная цена
  ЕИС не округляется; публичный отчёт отдаёт деньги с двумя знаками.
- `backend/app/config.py`: `Rules`, `SourceConfig`, `DeliveryPolicy`,
  `CalculationSnapshot(calc_date, rules, cpi)`, загрузка и атомарная запись YAML.
- `backend/app/units.py`: `parse_price`, `canonical_unit`, `convert`.
  Фасовка представлена `Offer.amount` и `amount_unit`; упаковка не приравнивается
  автоматически к пачке или штуке. Неизвестные единицы совместимы только сами с собой.
- `backend/app/pipeline/normalize.py`: приведение единицы ТЗ, НДС, индексация,
  доставка, отбор одной цены от поставщика и подсказки о разбросе.
- `backend/app/pipeline/calc.py`: выбросы, статистика, НМЦК. Все вычисления —
  `Decimal`, денежное округление — `ROUND_HALF_UP`.
- `backend/app/pipeline/extract_text.py`: DOCX/PDF/TXT/MD. В DOCX параграфы и
  таблицы идут в порядке документа, ячейки разделены ` | `; вложенные таблицы
  сохраняются, горизонтально объединённые ячейки не дублируются.
- `backend/app/llm/client.py`: протокол `LLM` и `OpenRouterLLM`. Промпты этапа 2
  добавлены на этапе 2.

## Порядок расчёта

1. `normalize_price(offer, basis)`:
   `round(price / convert(amount, amount_unit, basis.unit) * basis.per_tz_unit, 2)`.
2. `resolve_vat`, `index_price`, `resolve_delivery` возвращают решения с основанием.
   Сумма для порога доставки = базовая цена × количество ТЗ, до НДС и индексации.
3. `adjusted_price`:
   `round(base_price * vat.factor * indexation.factor, 2) + delivery.added_per_unit`.
4. `pick_per_supplier`: ИНН → название без организационной формы → домен.
   ЕИС и маркетплейсы без сведений о продавце не объединяются по домену.
   Остаётся самая свежая дата, затем меньшая расчётная цена, затем меньший id.
5. `find_outliers` исключает цены за коридором. При n ≥ 5 — inclusive IQR,
   иначе отклонение от медианы; пороги берутся из правил. Равенство границе допустимо.
6. `calculate` получает уже отфильтрованные цены. Передайте также
   `outlier_prices=исходные_цены`, чтобы медиана и коридор в `Stats` описывали
   исходную выборку. СКО считается с n−1, CV проверяется до округления.
7. При статусе `ok` НМЦК за единицу = среднее; итог позиции = эта цена × количество
   ТЗ с округлением до копеек. При недостатке цен/неоднородности `unit_price=None`,
   среднее доступно только как `reference_price`. Пустая выборка не имеет статистики.
   `diagnose_spread` объясняет возможные причины разброса, не меняя выборку.

Дата расчёта передаётся явно. Индексация не использует текущую дату процесса.
Код ядра не вызывает LLM и внешние сервисы. `build_position`/`build_report`,
агрегация итогов закупки и каскад источников описаны в `backend-search.md`.

## Правила и первичные источники

Шаблоны лежат в `backend/config/`, входят в wheel и Docker-образ. При запуске
недостающие файлы копируются в `CONFIG_DIR` (по умолчанию `DATA_DIR/config`),
существующие не перезаписываются. Неверный конфиг останавливает запуск с ошибкой
валидации. Для записи используйте `save_config(path, data)`: неизвестные поля и
недопустимые значения отклоняются до атомарной замены файла.

- Основная ставка НДС `0.22` проверена по [ФНС: налоги 2026](https://www.nalog.gov.ru/new2026/).
  Явная ставка страницы (включая нулевую) приоритетнее настройки. Конечная цена
  ЕИС с пометкой «Без НДС» не увеличивается. Неизвестный НДС не угадывается.
- Сумма месячных приращений ИПЦ соответствует формуле п. 3.18 рекомендаций № 567;
  сверка — [методические материалы органа закупок Свердловской области, п. 3.18](https://torgi.egov66.ru/site/upload/root/2025/%D0%9C%D0%B0%D0%B9/%D0%9C%D0%B5%D1%82%D0%BE%D0%B4%D0%B8%D1%87%D0%B5%D1%81%D0%BA%D0%B8%D0%B5%20%D1%80%D0%B5%D0%BA%D0%BE%D0%BC%D0%B5%D0%BD%D0%B4%D0%B0%D1%86%D0%B8%D0%B8%20%D0%BE%D0%B1%D0%BE%D1%81%D0%BD%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5%20%D0%9D%D0%9C%D0%A6%D0%9A%20%28%D0%B0%D0%BA%D1%82%D1%83%D0%B0%D0%BB%D0%B8%D0%B7%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%BE%20%D0%BD%D0%B0%2010.04.2025%29.pdf).
  Это не произведение месячных индексов. Конвенция проекта из плана: включаются
  полные месяцы после месяца цены до месяца перед расчётом. Она задана явно,
  отдельно от цитирования рекомендации. Старше шести месяцев — по разнице
  календарных месяцев, не по дням. Порог настраивается.
- Полный ряд [месячных ИПЦ РФ Росстата](https://rosstat.gov.ru/statistics/price)
  за 2023–2026 не получен: обе версии страницы с/без `www` завершились тайм-аутом.
  `cpi.yaml` оставлен пустым с объяснением, как допускает план. Это ограничение
  данных, а не фиктивные индексы. При отсутствии всех месяцев — `no_data`, factor=1;
  при частичных данных используются доступные месяцы и перечисляются пропуски.
  До живого расчёта старых цен нужно загрузить проверенный ряд ИПЦ.
- Универсальный порог бесплатной доставки юрлицам по всей МО не подтверждён.
  [Страница Комус](https://www.komus.ru/delivery/) недоступна при проверке;
  [условия ВсеИнструменты](https://www.vseinstrumenti.ru/legal/user-agreement/)
  предусматривают тарифы и частные акции. `site_delivery` оставлен пустым.
  При отсутствии условий доставка получает `unknown`, без выдуманной надбавки.
  Допущения по НДС магазинов и доставке ЕИС подписаны в YAML и решениях кода.

Пороги выбросов, CV, минимальное количество цен и порядок поправок — методика
проекта; текст `methodology_note` явно оговаривает применение законодательства
44-ФЗ и положения о закупке заказчика по 223-ФЗ.

## Извлечение ТЗ

Три исходных DOCX скопированы из `docs/` в тестовые фикстуры без изменений:
бумага — 5 876 символов, цитокины — 14 423, принтер — 5 707. Проверены таблицы,
количества, марки и характеристики, ОКПД2, условия доставки.

TXT/MD читаются как UTF-8 с поддержкой BOM. Для PDF используется текстовый слой
с сохранением расположения; OCR не входит в этап. Пустые файлы, повреждённые
документы, защищённый PDF и скан без текста возвращают понятный `ValueError`.
Лимит файла — 20 МиБ, распакованного DOCX — 100 МиБ. На этапе API превышение
лимита файла должно отображаться как HTTP 413.

## OpenRouter

Модель по умолчанию — `deepseek/deepseek-v4.1-flash`; пустая переменная окружения тоже
выбирает её. Идентификатор и поддержка инструментов/JSON-схем проверены по
[карточке OpenRouter](https://openrouter.ai/deepseek/deepseek-v4.1-flash).

`complete_json` отправляет `response_format=json_schema`, `strict=true` и
`provider.require_parameters=true`, проверяет ответ локально по JSON Schema.
Некорректный JSON, несоответствие схеме или неполный ответ повторяется один раз.
Дробные числа JSON читаются через Decimal без промежуточного float.
`chat` возвращает assistant-сообщение, проверяя форму вызовов и имена инструментов;
валидация параметров и исполнение инструментов относятся к этапу 3.

Документация: [Structured Outputs](https://openrouter.ai/docs/guides/features/structured-outputs),
[ошибки OpenRouter](https://openrouter.ai/docs/api/reference/errors).

Для сетевых ошибок, HTTP 429 и 5xx — до трёх попыток на запрос, задержки 1/2 с;
числовой `Retry-After` учитывается до 30 с. На один `complete_json` максимум шесть
HTTP-попыток с учётом исправления формата. HTTP 401/403 → `LLMAuthError`,
402 и прочие ошибки сервиса → `LLMServiceError`. Тела ошибок провайдера и ключ
не попадают в пользовательские сообщения исключений. HTTP 200 с полем `error`
тоже обрабатывается. При внешнем `AsyncClient` его закрывает вызывающий код;
собственный клиент закрывается через `async with` или `aclose()`.

Живой LLM-прогон не выполнялся. Все HTTP-ответы в тестах подменены
`httpx.MockTransport`; ключ и сеть для проверок не требуются.
