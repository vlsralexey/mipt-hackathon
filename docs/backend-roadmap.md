Этот маршрут задаёт порядок работ; он не меняет API или методику расчёта.

## Цель P0

ТЗ → позиции и уточнения → поиск в ЕИС и открытом вебе → сопоставление предложений
→ приведение цен → расчёт НМЦК → отчёт. Через чат пользователь может исправить
данные и выборку, получить новую версию, отменить правку и выгрузить DOCX.

Стек: Python 3.12, FastAPI, Pydantic v2, SQLite, OpenRouter. Локальный запуск через
Docker Compose; фронтенд React/Vite разрабатывается отдельно по API-контракту.
Playwright и управляемый Chromium добавляются на P1.

## Неизменные принципы

- LLM извлекает и сравнивает; все деньги, поправки и статистику считает код на
  `Decimal`. В API деньги передаются строками с двумя знаками после точки.
- Исходные предложения не перезаписываются правками. Отчёт собирается из
  результатов поиска и действующих правок; одинаковый вход даёт одинаковый итог.
- Уточнения имеют ответ по умолчанию и не блокируют прогон.
- У каждой цены есть источник и время получения, у исключения — причина.
- Пороговые значения и методика живут в конфиге. Ставки и индексы проверяются по
  первичным источникам при реализации; отсутствующие данные не выдумываются.

## Как продолжать в другом чате

Начальный запрос:

> Прочитай AGENTS.md и docs/backend-roadmap.md. Продолжи первый незавершённый
> этап с учётом API-контракта и спеки правок. Перед изменениями проверь ветку и
> состояние Git; после завершённых шагов сделай коммиты и обнови маршрут.

Каждая отдельная задача бэкенда — ветка `agents/<тема>` от актуального
`dev-backend`. Продолжение той же задачи возможно в её существующей ветке.
Перенос в `dev-backend` — одним squash-коммитом на задачу по просьбе пользователя.
Push — только по просьбе пользователя. Пока ветка не перенесена в `dev-backend`,
другим чатам нужно явно указать её имя, чтобы они видели новые документы и код.
