# Правила для ИИ-агентов

## Бэкенд: с чего начинать

- Актуальный маршрут работ и состояние этапов: `docs/backend-roadmap.md`.
- Контракт с фронтендом: `docs/api.md`; примеры: `docs/api-examples/`.
- Перед реализацией этапа прочитай ссылки из маршрута. Старый подробный план
  используется с поправками из спеки правок отчёта и API-контракта.
- После завершения этапа обновляй его состояние в маршруте и указывай проверки.

## Git

Работай в ветке `agents/<тема>` — там можно свободно делать коммиты. Ветку создавай
от актуального `dev`; тема — короткое имя латиницей через дефис
(`agents/backend-skeleton`, `agents/chat-ui`). Одна ветка — одна задача.

- Коммить сам, без отдельной просьбы, после каждого завершённого шага.
- Напрямую в `dev` и `main` не коммить, если пользователь не попросил об этом явно.
- В коммит добавляй только файлы, относящиеся к задаче: перед коммитом смотри
  `git status` и `git diff --staged`, не делай `git add -A` вслепую.
- Не коммить секреты, `.env`, ключи API и локальные настройки инструментов.
- Сообщения коммитов — на русском, кратко. Допустимы префиксы `feat:`, `fix:`,
  `docs:`, `refactor:`, `test:`, `chore:`.

### Перенос в `dev`

Когда пользователь просит — перенеси ветку в `dev` одним squash-коммитом:

```bash
git checkout dev
git merge --squash agents/<тема>
git commit   # сообщение — итог всей работы в ветке
git branch -D agents/<тема>   # если пользователь не просил оставить ветку
```

При конфликтах остановись и покажи их пользователю, не разрешай наугад.

### Push

`git push` — только по просьбе пользователя.
